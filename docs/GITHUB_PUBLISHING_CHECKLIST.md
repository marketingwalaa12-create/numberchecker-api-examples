# GitHub Publishing Checklist

Use this checklist when publishing the NumberChecker API examples as a public GitHub repository.

## 1. Create The Repository

Recommended repository name:

```text
numberchecker-api-examples
```

Recommended description:

```text
API examples for bulk WhatsApp number checker, phone status, RCS, iOS, Telegram, and email verification with NumberChecker.cloud
```

Keep the repository public so Google and GitHub search can discover it.

## 2. Upload These Files

Upload the complete `numberchecker-api-examples` folder, including:

- `README.md`
- `SERVICES.md`
- `.env.example`
- `examples/curl/whatsapp-checker.sh`
- `examples/python/whatsapp_checker.py`
- `examples/node/whatsapp-checker.mjs`
- `examples/php/whatsapp_checker.php`
- `sample-data/numbers.txt`

Do not upload a real `.env` file. Do not upload real API keys.

## 3. Add GitHub Topics

Use topics like:

```text
whatsapp-api
number-checker
phone-validation
csv-verification
lead-cleaning
rcs-checker
imessage-checker
email-verification
telegram-checker
bulk-verification
```

These help GitHub understand the repository and can help people find it through search.

## 4. Link It From Your Own Properties

After the repo is public, add links to it from:

- Main API docs: `https://docs.numberchecker.cloud`
- Website footer or developer/API area: `https://www.numberchecker.cloud`
- WhatsApp checker page
- Phone status page
- RCS checker page
- iOS status page
- Email verification page
- Telegram service page, if available

Good anchor text examples:

- `NumberChecker API examples`
- `WhatsApp Number Checker API examples`
- `Bulk contact verification API examples`
- `GitHub examples for phone number validation`

## 5. Use It In Content

Use this repo when making useful content:

- Blog post: "How to validate a WhatsApp contact list before a campaign"
- Blog post: "How to check phone number status from a TXT file"
- YouTube video: "Bulk WhatsApp number checker API demo"
- Telegram post: "Developer examples for NumberChecker.cloud API"

Each content piece should solve a real user problem. Do not copy-paste the same text everywhere.

## 6. Keep It Accurate

Update the repo when:

- API endpoints change
- Required fields change
- Service slugs change
- Upload limits change
- Product pages change
- New examples are added

Recommended update rhythm: check once per month, or whenever you change the API panel.

## 7. Safety Rules

- Never commit real API keys.
- Never upload real customer contact lists.
- Never publish private phone numbers or emails as sample data.
- Never promise guaranteed campaign results.
- Keep wording focused on data quality, verification, compliance, and integration.

## 8. Simple Success Metric

This repo is doing its job if:

- Customers can understand the API faster.
- Your support conversations become shorter.
- Google indexes the GitHub repo and docs page.
- People search for API terms and find NumberChecker.cloud.
- The repo sends visitors back to your official website and docs.
